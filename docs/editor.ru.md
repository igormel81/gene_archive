# Онлайн-редактор

**[English version](editor.md)**

Редактор позволяет править сведения прямо в браузере, без JSON и командной строки: людей,
семьи, документы (с загрузкой сканов) и места. Он входит в сервер `gene serve`, поэтому на
статическом хостинге (GitHub Pages, Netlify) его нет — нужен свой сервер или Docker
([публикация](deploy.ru.md)).

Что он делает:

- **Вход по паролю**, у каждого своя учётная запись. Две роли: *редактор* правит сведения,
  *администратор* ещё и разбирает предложения читателей, возвращает прежние версии и
  управляет пользователями. PIN для читателей сайта остаётся как был и с редактором не связан.
- **Проверка перед сохранением.** Правка, после которой в данных появится ошибка (битая ссылка
  на человека или документ, непонятная дата), не сохраняется — редактор показывает, что не так.
  Ошибки, которые уже были в файле, не мешают править другие записи.
- **Даты по-человечески.** Можно писать «около 1899», «до 1950», «между 1900 и 1905»,
  «9.10.1899», «9 октября 1899» — в файл попадёт `ABT 1899`, `BEF 1950`, `BET 1900 AND 1905`,
  `1899-10-09`, `9 OCT 1899`.
- **Никто не затирает чужие правки.** Если двое открыли одну запись и первый сохранил, второй
  получит сообщение «запись изменил кто-то другой» вместо молчаливой перезаписи. Правки
  разных записей друг другу не мешают.
- **Журналы ведутся сами.** Каждое изменённое поле — строка в `corrections` (было, стало, кто,
  почему, на каком документе), каждое сохранение — строка в `research_log`. Это журнал
  исправлений на сайте.
- **История в git.** Каждое сохранение — коммит от имени автора правки. Если папка сайта ещё не
  git-репозиторий, редактор создаст его при первом запуске. Администратор может вернуть данные
  к любой версии (возврат — тоже новая правка, его можно отменить так же).
- **Сайт обновляется сам** через несколько секунд после сохранения; пока идёт сборка, работает
  прежняя версия. Если сборка не прошла, редактор покажет ошибку.
- **Предложения читателей.** В карточке человека на сайте появляется «Предложить исправление»:
  родственник выбирает, что исправить (дату или место рождения и смерти, имя или «другое»),
  пишет, как правильно и откуда это известно. Администратор видит предложения в разделе
  «Предложения» и применяет их одной кнопкой, открывает запись или отклоняет.
- **Проверка данных** (вкладка «Проверка», то же — `gene hints`): невозможные факты (родился
  после смерти матери, родитель моложе 14 лет, мать старше 55, отец старше 75, брак раньше 15 лет) и пробелы (нет дат, дата без документа,
  человек не связан с древом, документ ни к кому не привязан, место без координат) — список задач
  для следующего поиска, каждый пункт открывает запись.
- **Загрузка сканов и фото**: JPEG, PNG, WebP, GIF, PDF до 30 МБ. Фотографии пересохраняются
  (если установлен Pillow): поворачиваются как надо, из них удаляются сведения о камере и GPS.

## Как включить

```sh
gene users my-family add igor --role admin --display "Игорь"
# → одноразовая ссылка-приглашение, по ней задаётся пароль
gene serve my-family --editor
```

Откройте ссылку (или `http://127.0.0.1:8111/edit/` и войдите). Если в `site.json` указан
`base_url`, ссылка уже будет с адресом вашего сайта.

Чтобы на сайте появилась кнопка «Предложить исправление», в `site.json` должно быть
`"comments": true` (то есть сайт работает с сервером).

## Пользователи

Удобнее всего — в самом редакторе, раздел «Пользователи» (только администратор): «Создать и
получить ссылку», отправить ссылку родственнику — по ней он сам задаст пароль. Ссылка
одноразовая и действует 7 дней; «Новая ссылка» — если устарела или пароль забыт.

То же из командной строки:

```sh
gene users my-family list
gene users my-family add anna --display "Тётя Анна"           # редактор
gene users my-family add petr --role admin                    # администратор
gene users my-family invite anna                              # новая ссылка (сброс пароля)
gene users my-family role anna admin
gene users my-family disable anna                             # отключить; enable — включить
gene users my-family passwd igor                              # задать пароль здесь же
```

Логин — латиницей (`anna`, `anna.k`); имя (`--display`) — как подписывать правки в истории и
журнале исправлений. Пароль — не короче 10 знаков; хранится только его хеш (scrypt).

## Docker

```yaml
services:
  gene:
    image: ghcr.io/igormel81/gene_archive:latest
    ports: ["127.0.0.1:8111:8111"]
    volumes:
      - ./my-family:/site          # без ":ro" — редактор пишет в папку
      - gene-state:/state
    environment:
      GENE_EDITOR: /site
    user: "1000:1000"              # владелец папки my-family (команда id -u; id -g)
```

Пользователи: `docker compose exec gene gene users /site add igor --role admin`.

## Безопасность

- Редактор открывайте только по **HTTPS** (Caddy, nginx — см. [публикацию](deploy.ru.md)):
  cookie входа помечена `Secure` и по обычному http не отправляется (кроме `127.0.0.1`).
- Вход: не больше 10 неудачных попыток за 15 минут с одного адреса и для одного логина.
- Сессия — 30 дней; смена пароля и отключение пользователя завершают все его сессии.
- Запросы на изменение принимаются только со страницы редактора (заголовок клиента и
  CSRF-токен сессии, cookie `SameSite=Strict`), страница редактора не встраивается в чужие сайты.
- Редактор видит **все** сведения, в том числе о живых людях, — давайте доступ только тем,
  кому доверяете. Опубликованный сайт по-прежнему скрывает живых.
- Журнал входов и действий — таблица `audit` в `<state>/editor.db`.

## Резервные копии

Всё, что нужно сохранить: папку сайта (вместе с `.git` — это вся история правок) и папку
состояния (`.gene-state` или том Docker: `editor.db` с пользователями и предложениями,
`comments.db`). Удобно раз в день отправлять репозиторий в закрытый репозиторий на GitHub:
`git push` из папки сайта.

## Чего в редакторе нет

Поля без формы — места жительства, профили на других сайтах, альтернативные версии дат,
хронология и материалы мест — правятся в блоке «Другие поля (JSON)» той же записи, в формате
`family_tree.json`. Наводки (`research_leads`), страницы `content/` и `site.json` правятся в
файлах, как раньше; ИИ-помощники — [ai-assistants.ru.md](ai-assistants.ru.md).
