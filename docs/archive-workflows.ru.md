# Резервная копия, предпросмотр публикации и пакетные правки

## Резервная копия

```sh
gene backup my-family -o ../family-backup.tar.gz
# Если сервер хранит комментарии и пользователей отдельно:
gene backup my-family -o ../family-backup.tar.gz --state /path/to/server-state
gene restore ../family-backup.tar.gz --check
gene restore ../family-backup.tar.gz restored-family
```

Копия включает исходные данные и настройки, документы (в том числе скрытые и не
отслеживаемые Git), тексты, переводы, историю Git и состояние сервера: комментарии,
пользователей, предложения, журнал действий. Для SQLite используется backup API,
поэтому учитываются подтверждённые записи из WAL. Каждая база получается целостной;
для единого момента времени между несколькими базами остановите запись на сервере.
Укажите `--state`, если используется отдельная папка состояния: команда не ищет её
на других компьютерах или в конфигурации развёртывания.

Сборки `_site/`, `_site.*`, каталоги с маркером `.gene-archive-output`, кэши, виртуальное
окружение `.venv`, `node_modules` и временные файлы редактора не включаются. Символические
ссылки и специальные файлы отклоняются: реальные документы должны лежать внутри архива.
История переносится через Git bundle; конфигурация remote, hooks и индекс staging не
переносятся. Незакоммиченные рабочие файлы сохраняются. Для Git-истории корень семейного
архива должен совпадать с корнем репозитория.

**Копия приватная и не зашифрована.** Она содержит сведения о живых и хеши паролей.
Файл создаётся с правами 600; храните его вне публичных каталогов и исходного архива.
Существующий файл копии не перезаписывается. Контрольные суммы выявляют повреждение,
но не доказывают происхождение файла: восстанавливайте только свои доверенные копии.

`restore --check` проверяет пути, SHA-256, базы и историю, затем действительно собирает
сайт во временной папке. Команда не меняет исходный архив. При ошибке проверка завершается
с ненулевым кодом. Пределы: менее 100 000 файлов, распакованный размер до 100 GiB,
манифест до 16 MiB. Восстановление разрешено только в **новую** папку и публикует её
после успешной проверки. Состояние сервера окажется в `restored-family/.gene-state`.
Пользователи и пароли сохраняются, сеансы и приглашения сбрасываются, секрет cookie
обновляется: нужно войти заново и при необходимости перевыпустить приглашения.
Пароли, PIN, переменные окружения, reverse proxy и сервис на другом сервере команда
не настраивает. После переноса укажите новый путь состояния в команде запуска сервера.

## Предпросмотр публикации

```sh
gene publish-preview my-family
gene publish-preview my-family --json > publication.json
```

Сборка выполняется на временной копии. Исходные JSON, Git, готовый сайт и кэш не
меняются; для согласованного чтения используется обычный файл блокировки в `.gene-state`.
Отчёт содержит:

- для людей: применяется ли защита живых и какие поля изменены или скрыты;
- для документов: публикуется ли карточка, причина исключения, скрытые поля почты,
  какие оригинальные файлы всё-таки попали в вывод;
- для журналов: число открытых/скрытых записей, решения по индексам (с нуля) и причины;
- полный список файлов фактической сборки с размером и SHA-256 (`--json`);
- предупреждения сборки и пропущенные переводы.

В отчёт не выводятся значения скрытых фактов и тексты закрытых журналов, но номера,
имена файлов и общая структура могут быть приватными. Отчёт не предназначен для сайта.

При ручной ссылке на скрытый документ из content/media его файл может попасть в
сборку — предпросмотр выделяет это предупреждением. Произвольный HTML, изображения
из `img/` и данные `geo/` публикуются как есть: их содержание нужно проверить вручную.
Это проверка конкретного снимка; последующие изменения требуют нового предпросмотра.

## Пакет правок одной транзакцией

```json
[
  {"kind":"source","as":"register","record":{"title":"Метрическая книга: пример","kind":"church_record"}},
  {"kind":"person","as":"anna","record":{"given_names":"Анна","surname":"Примерова","birth":{"date":"1900-01-02","source_ids":[{"$ref":"register"}]}}},
  {"kind":"family","record":{"partners":["I1"],"children":[{"$ref":"anna"}],"source_ids":[{"$ref":"register"}]}}
]
```

```sh
gene apply my-family changes.json --atomic --dry-run
# base_version из ответа предпросмотра защищает от записи поверх новой версии:
gene apply my-family changes.json --atomic --if-version VERSION --build
```

Сначала весь пакет выполняется в памяти под общей блокировкой. Каждая операция
проходит обычные проверки редактора; документы добавляйте раньше фактов, а людей —
раньше семей. Только после успеха всех операций данные сохраняются один раз,
с журналами каждой правки и одним коммитом пакета. При первом использовании Git
дополнительно создаётся начальный коммит истории. Ошибка проверки или коммита не
сохраняет часть пакета. Пересборка выполняется после сохранения: её отказ не отменяет
уже записанные данные и коммит; команда возвращает `build_error`.

`as` задаёт уникальное имя операции. Объект `{"$ref":"anna"}` заменяется номером,
выданным этой записи в предыдущей операции того же пакета. Ссылки вперёд и неизвестные
имена отклоняются. Предпросмотр видит результаты предыдущих операций в памяти,
но не резервирует номера. `--if-version` сравнивает версию family_tree.json; настройки
и файлы документов в этот номер не входят. Без `--atomic` сохранено прежнее поведение:
отдельная запись и коммит для каждой операции. В редакторе браузера новые команды
пока не представлены отдельными экранами.
