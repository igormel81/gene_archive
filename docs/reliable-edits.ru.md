# Надёжная запись и публикация журналов (0.7)

Редактор, `gene apply` и сборка используют общую блокировку папки, в том числе между
локальными процессами. Под блокировкой выполняются чтение, проверка, атомарная запись
и git-коммит. Не запускайте посторонние команды git в той же папке во время сохранения.
Если коммит не удался, возвращается ошибка, JSON и индекс git восстанавливаются.
Без установленного git по-прежнему можно работать без истории (`commit: null`).
Если коммит уже сделан, а запуск пересборки не удался, ответ явно указывает, что данные
сохранены; выполненный коммит не отменяется.

Выход сборки не может заменять исходный архив, его предков и папки ресурсов. Непустой
каталог, не похожий на собранный сайт, не перезаписывается. Временные папки имеют
уникальные имена; чужие `.build` и `.old` не удаляются. При ошибке замены вывода
восстанавливается предыдущая сборка.

Удалённые номера не переиспользуются. `id_counters` хранит максимальные выданные
номера I/F/S/L/R/C, включая историю и номера до восстановления старой версии.
Не уменьшайте счётчики. Старый архив получит их при первом сохранении.

## Журналы закрыты до проверки

При `privacy.hide_living=true` (по умолчанию) записи `research_log` и `corrections`
публикуются только с `"visibility":"public"`. Это касается и старых записей:
они остаются в `family_tree.json`, но не показываются на публичном сайте до проверки.
Редактор и `gene apply` создают закрытые записи. Известные ссылки на живых людей
и семьи скрываются даже при public.

Проверьте всю запись: причину, прежнее/новое значение, результат поиска и scope.
Не открывайте весь старый журнал автоматически: свободный текст может рассказывать
о другом живом человеке. Произвольные тексты в «Истории» автоматически не обезличиваются.
В демонстрационном архиве журналы вымышленные и явно отмечены как public.

Проверенную запись поиска можно добавить так:

```json
{"op":"log","action":"Поиск в указателе: приход, годы","result":"Совпадений в просмотренном указателе нет","visibility":"public"}
```

При `privacy.hide_living=false` журналы сохраняются в публикации полностью — это
выбор владельца для его режима приватности. Исходные закрытые записи сборка не удаляет.

## Источники поиска и учёт прочитанного

`gene apply` принимает `kind: "research_resources"` (R#) и `kind: "coverage"` (C#):
с dry_run, проверками, журналами и историей git.

```json
[
  {"kind":"research_resources","record":{"name":"Пример архива","url":"https://example.org"}},
  {"kind":"coverage","record":{"parish":"Пример прихода","resource_id":"R1","entries":[{"year":1858,"part":"revisions","status":"partial","up_to":"двор 4","film":"Дело 12","frames":"листы 1–8"}]}}
]
```

В существующем архиве используйте номер R#, возвращённый первым сохранением.
Для обновления передавайте id, для удаления — `op: "delete"`. Массив запросов —
отдельные последовательные операции, а не единая транзакция. Dry-run не резервирует
номера и не делает результат первого предпросмотра видимым следующему: зависимые
правки проверяйте отдельно после сохранения предыдущей.

Части: births, marriages, deaths, confessions, revisions, census — рождения, браки,
смерти, исповедные ведомости, ревизии, переписи. Для старой строки coverage без номера
передайте её исходный объект целиком в base; номер C# получит только изменяемая строка.
Устаревший или неоднозначный base не принимается.

```json
{"kind":"coverage","base":{"parish":"Пример прихода","entries":[]},"record":{"entries":[{"year":1858,"part":"revisions","status":"complete"}]}}
```

В наводках сохраняются next, checked, stage, blocked_by, expected_sources.
Движок не выводит разрешения из текста и не переносит ограничения одной семьи на всех.
Каталог и сетевой поиск остаются задачей genealogy-mcp; этот выпуск меняет только gene-archive.
